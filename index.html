Monitor NOC

Herramienta portable para Windows que centraliza ping ICMP, TCP Connect, escaneo de red por segmento /24 vía ARP/ping sweep y acceso remoto directo por VNC y SSH (requiere tener instalado algún cliente VNC y SSH en el equipo), sobre múltiples hosts en paralelo sin lentitud en la interfaz. Sustituye el uso disperso de ping y tracert por reportes HTML con umbrales de alerta configurables según el estándar de cada empresa.

Estructura de un nodo

NODE_1 ───────────────────────────────────── TARGET: 1.1.1.1 NODE: NODE_1 5 ms S.O | TTL: Linux / macOS / Android | TTL: 57 ■ STOP PING REMOVER PKT SENT: 4 | PKT LOSS: 0 (0.0%) | AVG LATENC: 5 ms REMOTING: VNC · SSH

El campo S.O | TTL es una estimación basada en el TTL de respuesta; no es una huella digital exacta del sistema operativo.

Diagnóstico completo — 5 fases

Desde cualquier nodo se puede abrir una ventana con el botón DIAGNOSTICAR, que ejecuta estas fases en orden:

  • TracerouteRuta completa hacia el destino, con resolución DNS por cada salto.
  • DNSResolución directa del destino, PTR del destino y PTR de cada salto de la ruta.
  • Ping extendido20 pings adicionales: pérdida, latencia, jitter y un veredicto de calidad de enlace.
  • Escaneo de puertosClasifica puertos como ABIERTO, CERRADO o FILTRADO.
  • Descubrimiento de MTUCalcula la MTU efectiva del enlace mediante búsqueda binaria.

Tiempo de espera

El diagnóstico completo puede tardar hasta un par de minutos: prueba varios puertos y calcula la MTU real. No es instantáneo por diseño.

Cuando ICMP está bloqueado por firewall, TCP valida el servicio directamente contra el puerto real (80, 443, 22, etc.) mediante conexión de socket, con el mismo motor de métricas en vivo que ICMP.

Parámetros configurables

◆TARGETHost o IP a probar (ej. google.com)
◆PORTPuerto por defecto: 80 (editable a cualquier puerto TCP)
◆NODENombre identificador del monitor (ej. TCP_NODE_1)
◆TIMEOUT (s)Segundos de espera antes de marcar el intento como fallido
◆INTERVAL (s)Segundos entre cada intento de conexión
◆COUNTNúmero fijo de intentos; 0 = monitoreo continuo

Métricas en vivo

SENT, RECEIVED, LOST, LOSS% y LATENCY (MIN/MAX/AVERAGE), igual que en el módulo ICMP, con el resultado reflejado en tiempo real en el panel LIVE.

Cuándo usar TCP en lugar de ICMP

Muchos firewalls corporativos bloquean ICMP pero permiten tráfico HTTP/HTTPS. Si un host nunca responde al ping pero el servicio funciona en el navegador, valida con TCP sobre el puerto 80 o 443 antes de reportar el nodo como caído.

El botón REPORT → VIEW REPORT genera un dashboard HTML autocontenido con el estado consolidado de todos los nodos monitoreados, útil como evidencia de disponibilidad o soporte de SLA. Incluye modo claro/oscuro y botón de descarga.

Configuración de umbrales

Desde REPORT → SETTINGS se abre CONFIGURACIÓN DE REPORTE, donde se ajustan los umbrales de alerta de red usados por el reporte.

UmbralQué hace
Estado Advertencia (seg.)Segundos de corte seguido para pasar el nodo a ADVERTENCIA
Estado Crítico (seg.)Segundos de corte seguido para pasar el nodo a CRÍTICO

EXCLUSIVO EDICIÓN SERVER

La edición SERVER incluye todo lo de la edición Standard, más un servidor web en tiempo real embebido que publica el estado de ALERT-ROUTING en una página accesible desde la LAN o internet, con clientes de solo lectura.

Configuración del servidor web

Qué se configura

  • Puerto: puerto TCP de la página web (8765 por defecto, editable)
  • Contraseña: opcional, protege el acceso a la página publicada
  • Compartir en la red: casilla que habilita el acceso de solo lectura desde otros equipos de la LAN (o internet, si se publica el puerto)
  • URLs: se listan automáticamente para 127.0.0.1 y cada IP LAN del equipo

Página web en vivo

Clientes conectados (solo lectura)

Publicación LAN / internet

La página puede compartirse dentro de la LAN o publicarse hacia internet (redirigiendo el puerto en el router), según decida el administrador.

Exportar dashboard

El estado consolidado de ALERT-ROUTING visible en la página puede exportarse como dashboard, igual que el reporte HTML del módulo REPORTE.

Clientes de solo lectura

Cualquier equipo que acceda a la página publicada puede ver el estado en vivo, pero no puede editar ni añadir monitores: la gestión queda solo en el equipo servidor.

Alcance de este panel

ALERT-ROUTING vigila la continuidad de los equipos de cada local y está disponible en ambas ediciones. Este panel documenta exclusivamente el servidor web de la edición SERVER, que expone ese mismo monitoreo como página compartible en red, con su propio listado de clientes conectados.

Activación

  • Copia el ID del equipoAl abrir Monitor NOC por primera vez aparece la ventana de activación con el ID de ese equipo (MNOC-XXXXX-XXXXX-XXXXX-XXXXX) y el botón COPIAR.
  • Pulsa "PEDIR LICENCIA/LLAVE"Mismo botón de la ventana de activación: envía el ID por WhatsApp al administrador sin necesidad de copiarlo a mano. Recibirás un código de activación, válido solo para ese equipo.
  • Pega el código y ACTIVARListo: no vuelve a pedirlo hasta el vencimiento (avisa 30 días antes).

Bueno saber

  • Un código sirve para un solo equipo: copiado en otra PC no funciona.
  • La activación queda guardada en el equipo, fuera de la carpeta del programa: borrar y volver a copiar el portable no la pierde.
  • Si cambias de PC, pide un código nuevo con el ID de la nueva.
